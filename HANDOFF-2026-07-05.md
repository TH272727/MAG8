## New load-bearing invariants (created Phases 1–4; do not break)

1. **Public-view boundary** — no client payload (SSE frame, snapshot JSON, RSC prop into a
   client component) may bypass `lib/public-view.ts`. The three boundaries: SSE `send()` in
   `app/api/runs/[runId]/stream/route.ts`, snapshot GET in `app/api/runs/[runId]/route.ts`,
   and the server pages `app/runs/[runId]/page.tsx` (→ `toPublicSnapshot`),
   `app/stocks/[ticker]/page.tsx` (→ `toPublicLensRow` + `sanitizeRankedStock`),
   `app/rankings/page.tsx` (→ `toPublicReport` + `LENS_TO_PUBLIC` keys).
   Internal skill ids stay in DB/persisted events/prompts; historical rows translate on the way out.
2. **Public lens vocabulary** — client code keys everything by `PublicLens`
   (`fundamentals | macro | consensus`, order matches `LENS_SKILLS`) from `lib/public-lens.ts`
   (client-safe, type-only server imports). `lens_status` events reach the browser with a `lens`
   field, never `skill`. Compiler reports are generated ALREADY-public (public lens keys +
   `sanitizeError` at source in `lib/orchestrator/compiler.ts`) because reports are persisted
   publishable artifacts; events sanitize at the boundary instead.
3. **Model-authored text discipline** — all three stage prompts pin: public report titles
   ("Fundamentals — TICKER" etc.) and never mention tools/skills/SKILL.md/session/platform.
4. **Modifier semantics** — `RunParams.modifier` (≤280, `sanitizeModifier()` in `lib/schemas.ts`
   strips fences/backticks/control chars) scopes **discovery only**; lens stage is modifier-blind
   BY DESIGN so the weekly lens cache stays valid; compiler gets it echoed for `marketOverview`.
   It rides `runs.params_json` — no DDL. Injected as a subordinate block in `discoveryPrompt`
   that re-asserts universe/count/contract supremacy.
5. **Retry-proof wire extension pattern** — any new keyMetrics field must be
   `.optional().catch(undefined)` + tolerant preprocess, arrays slice-capped in preprocess
   (`capArray(n)`), NEVER `.max()` rejection. Proven: malformed optional fields drop without
   triggering the corrective retry. GT player m/e/c are 1–10 (matches the skill's own rubric —
   pinning 1–5 would recreate the 2026-07-03 retry storms).
6. **Migration pattern** — `migrate()` in `lib/db.ts`: `SCHEMA_SQL` always carries the LATEST
   shape; version-gated, column-check-guarded ALTERs upgrade existing files; currently
   `user_version = 2` (added `lens_analyses.num_turns`).
7. **Compiler prompt slimming** — `players`/`institutions` are stripped from compiler lensData
   (display-only rosters); `scenarios`/`horizonProbabilities` stay (they inform scoring).
8. Everything from CLAUDE.md still holds (persist-before-emit, compress:false, fence contract,
   gold-for-verdicts-only, explicit `grid-cols-1` bases, demo week keys, etc.).

## Environment gotchas hit this session (beyond CLAUDE.md's list)

- **Multi-line `npx tsx -e '...'` (single-quoted) silently prints nothing** in this Git-Bash-on-Windows
  setup. Write a temp probe file instead (pattern used: `scripts/__*-probe.ts`, run, delete). Short
  double-quoted one-liners work.
- **The Write tool once mangled ` `-style escapes into literal control bytes** (schemas.ts became
  "binary" to grep). Fixed via a node script replacing the class with `[\x00-\x1f\x7f]`. If you write
  regexes with control-char classes, prefer `\x`-escapes and verify with `grep -c` afterwards.
- Killing the dev server: `powershell -NoProfile -Command "Get-NetTCPConnection -LocalPort 3000 ..."`
  (see CLAUDE.md). The dev server was stopped at handoff time.
- Mock error cell now surfaces publicly as "The analysis ran too long and was stopped." (sanitizeError
  maps the mock's "simulated lens timeout" text through the timeout category) — expected, not a bug.
- `git add -A` will sweep any uncommitted user changes — check `git status` before committing a phase.
